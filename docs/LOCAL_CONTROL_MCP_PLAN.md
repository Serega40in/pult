# PULT: план перехода к управлению из чата через MCP

> Статус: проектирование следующего этапа. Документ фиксирует целевую архитектуру; он не означает, что MCP-сервер или туннель уже реализованы.

## Цель

Пользователь пишет в чате обычным языком: «открой сайт, найди информацию, подготовь форму». ИИ вызывает ограниченные инструменты PULT, локальный агент выполняет разрешённые действия на компьютере и возвращает результат. Для необратимых внешних действий требуется отдельное подтверждение пользователя.

## Что уже есть

- Расширение Chrome/Edge выполняет небольшой набор действий на активной вкладке: переход, клик по CSS-селектору, ввод текста, прокрутка и ожидание.
- Python Desktop Agent умеет открыть URL или приложение, напечатать текст, нажать сочетание клавиш, показать уведомление и ждать.
- Пока нет единой точки входа API/MCP, проверки состояния агента из чата, структурированного чтения страницы и согласованного журнала выполнения.

## Целевая архитектура

1. **PULT Desktop Agent** — локальный процесс на компьютере. Только он получает право выполнять действия ОС.
2. **PULT Browser Bridge** — расширение Chrome/Edge, которое выполняет браузерные операции в явно выбранной вкладке и возвращает ограниченный результат.
3. **PULT MCP Server** — стабильный набор инструментов для ИИ-клиента. Сначала локальный запуск для разработки и тестов; затем подключение через поддерживаемый безопасный MCP-туннель.
4. **Policy / Approval Layer** — единое место проверки каждого действия, ограничения числа шагов, списка доменов и времени выполнения.
5. **Audit Log** — локальный журнал времени, инструмента, результата и идентификатора запроса. Не записывать пароли, cookie, токены и содержимое полей, помеченных как чувствительные.

Схема потока:

`Chat / AI → MCP tools → Policy + Approval → Desktop Agent / Browser Bridge → Result → Chat`

## Минимальные MCP-инструменты первой версии

- `pult_status()` — состояние агента, версия, платформа, готовность браузерного моста.
- `browser_active_tab()` — URL, заголовок и доступные сведения об активной вкладке; не возвращать cookie, local storage или пароли.
- `browser_read_page()` — текст страницы с ограничением длины и явным указанием текущего домена.
- `browser_navigate(url)` — переход на HTTP(S)-адрес после проверки URL.
- `browser_click(selector)` — клик по элементу на открытой вкладке; потенциально значимые действия требуют подтверждения.
- `browser_fill(selector, text)` — заполнение формы без отправки.
- `pult_preview_plan(plan)` — валидировать и показать план без исполнения.
- `pult_execute_plan(plan, approval)` — выполнить только валидированный план в пределах политики.

Позже можно добавить скриншоты, управление окнами и приложениями, скачивание файлов и операции с локальными файлами. Не включать универсальный shell/PowerShell-инструмент в первую версию.

## Обязательные меры безопасности

- Не публиковать порт локального агента в интернет и не делать его доступным для произвольных сайтов.
- Не полагаться только на CORS или секретный URL как на механизм авторизации.
- Для внешнего доступа использовать только поддерживаемый аутентифицированный канал, предпочтительно безопасный MCP-туннель. Не подменять его открытым порт-форвардингом.
- Разрешать только явно описанные операции. URL — только HTTP/HTTPS; ограничить длину плана, число шагов и длительность ожиданий.
- Разделить чтение, подготовку изменений и их отправку. Заполнение формы не равно нажатию Submit.
- Отдельное явное подтверждение пользователя необходимо перед публикацией, отправкой сообщения, оплатой/переводом, заказом, удалением данных, изменением прав доступа или запуском внешнего действия с существенными последствиями.
- У пользователя должен быть способ немедленно остановить работу агента; сохраняем текущий аварийный механизм PyAutoGUI.
- Секреты хранить локально, не коммитить в GitHub, не помещать в логи и не передавать модели.

## Этапы

### Этап 1 — локальная основа

- [ ] Ввести единый формат запросов и ответов.
- [ ] Разделить валидацию плана и исполнение.
- [ ] Добавить статусы, версии, таймауты и понятные ошибки.
- [ ] Добавить тесты для разрешённых, некорректных и опасных планов.
- [ ] Сохранить ручное подтверждение выполнения и аварийную остановку.

### Этап 2 — MCP

- [ ] Реализовать MCP-сервер с ограниченным перечнем инструментов.
- [ ] Начать с локальной разработки и тестов.
- [ ] Проверить совместимость клиента и формат транспорта.
- [ ] Для подключения из облачного ChatGPT использовать только доступный данному аккаунту поддерживаемый путь (например, Secure MCP Tunnel); доступность пользовательских MCP-инструментов и write-действий зависит от продукта и плана.

### Этап 3 — полноценный рабочий цикл

- [ ] ИИ получает состояние страницы.
- [ ] ИИ предлагает следующий шаг и показывает его смысл.
- [ ] Пользователь подтверждает действие, когда оно может иметь внешние последствия.
- [ ] PULT выполняет шаг и возвращает фактический результат.
- [ ] По результату ИИ решает, что делать дальше; при ошибке останавливается и объясняет проблему.

### Критерий готовности

Из поддерживаемого ИИ-клиента можно запросить «открой сайт и найди X», получить подтверждённое содержимое страницы, подготовить форму без отправки и отдельно подтвердить отправку. Никакие действия не выполняются скрытно, а произвольные команды ОС не доступны инструментам MCP.
